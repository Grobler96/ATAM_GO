## Security rules in force (13 Oct 2026 lockdown)
- Signed-out users get nothing: anon access to data is revoked; the browser sends the signed-in user's Supabase token.
- n8n webhooks check the login (a "Verify Login" step calls Supabase `/auth/v1/user`). The old shared token is gone.
- Any text from the database that goes into `innerHTML` must be escaped (`esc`, `escHtml`, or the shared `atamEsc` in `atamgo-auth.js`). The CDN scripts are pinned with integrity hashes.
- Row level security is on for every table (the last ten, the Xero sales and customer account tables, were fixed 20 Oct 2026: `sql/security_rls_xero_customer_tables_2026-10-20.sql`). Signed-in users can only read those; n8n writes with the service role. `vendor_xero_contact_override` and `xero_sync_state` are service-role only. New tables must have RLS on from the start.
- Functions that change data are security-definer and need a signed-in user. Do not loosen anon access to make something work; use the user's token instead.

Orders approved within an hour of creation are excluded from conversion rate. DecoNetwork has a Rejected status for quotes (customer rejects online, or staff use Mark Quote as Rejected), but nothing in the API data we read shows it: no quote has ever been cancelled before being approved, and quote #636368 (thought to be rejected) still reads as an ordinary open quote. So a rejected quote currently just ages to Lost after 30 days quiet. The Sales team tab shows each person's win rate change (and the whole team's) for Week, Month and Year: last 7 days / 30 days / 12 months against the equal period just before, in percentage points, same rule as the ring (won ÷ decided, by date decided). Year shows a dash until there is a fair year of data: unconverted quotes were only synced from about June 2026, so older months show almost 100% approved. A dashed chip means fewer than 5 decided quotes in one period.

## Handy facts
- Supabase tool quirks: `execute_sql` returns only the last statement's result; DROP statements hang; use plain `create or replace`.
- n8n tool quirks: after changing a workflow you must publish it; large workflow dumps are huge, so fetch only the nodes you need.
- DecoNetwork: when an order is edited it issues new workflow item ids and the old `sales_order_lines` rows stay behind. The outstanding-lines view ignores rows more than 5 minutes older than the newest row on the order (`sql/fix_stale_sales_order_lines_2026-10-13.sql`).
